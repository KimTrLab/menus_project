강의 필기: 비동기 작업과 요청 상태

핵심 개념
- 네트워크 요청은 즉시 끝나지 않는다. JavaScript는 기다리는 동안 다른 이벤트와 렌더링을 처리하고, 완료 결과를 나중에 받는다.
- Promise는 나중에 완료될 작업의 결과를 나타낸다. async/await는 그 결과를 순서대로 읽기 쉽게 작성하는 문법이다.
- 요청 결과를 받기 전에는 로딩, 완료 뒤에는 성공 또는 오류 상태를 화면에 표현한다.

요청부터 화면 표시까지
1. 컴포넌트가 화면에 나타나거나 요청 옵션이 바뀌면 useEffect가 요청을 시작한다.
2. 요청을 기다리는 동안 status를 loading으로 설정한다.
3. await가 Promise의 결과를 기다리는 동안 브라우저는 다른 작업을 계속 처리한다.
4. 성공하면 메뉴 데이터를 state에 저장하고, 실패하면 오류 메시지를 저장한다.
5. React가 state를 바탕으로 로딩·오류·빈 결과·목록 중 알맞은 화면을 렌더링한다.

왜 Effect cleanup이 필요한가?
- 첫 요청이 끝나기 전에 요청 조건이 바뀌면 두 번째 요청이 시작될 수 있다.
- 이전 요청의 결과가 나중에 도착하면 최신 화면을 오래된 데이터로 덮을 수 있다. 이를 오래된 요청 결과 문제로 볼 수 있다.
- cleanup에서 isActive를 false로 만들면 정리된 Effect의 결과가 state를 갱신하지 못하게 막는다.
- 이 예제는 결과 반영을 무시할 뿐 네트워크 작업 자체를 중단하지는 않는다. 실제 fetch 요청 취소는 AbortController로 확장할 수 있다.

예제에서의 요청 재실행
- 실패/빈 결과 설정이나 다시 요청 버튼은 Effect 의존성을 바꿔 요청을 다시 시작한다.
- 새 Effect가 시작되면 이전 Effect의 cleanup이 먼저 실행된다.
- 실패 응답에 요청 횟수를 표시해 재요청 결과를 구별한다.

모의 요청과 실제 요청
- setTimeout은 서버 응답까지 시간이 걸리는 상황을 흉내 낸다.
- 실제 서비스에서는 fetch 등으로 서버에 요청하고, 서버 응답도 검증해야 한다.
- 요청 성공과 데이터가 비어 있는 상태는 다르므로 별도로 표시한다.

생각해 보기
- 요청 중 사용자가 다른 조회 조건을 선택했을 때 이전 결과를 그대로 표시하면 어떤 문제가 생길까?
- Promise를 기다리는 동안 화면이 멈추지 않는 이유는 무엇일까?
