강의 필기: Server Component와 Client Component의 경계

핵심 개념
- Next.js App Router에서 컴포넌트는 별도 표시가 없으면 Server Component다.
- Server Component는 서버에서 화면에 필요한 내용을 준비할 수 있고, 그 컴포넌트 코드는 브라우저용 JavaScript로 전부 보내지 않는다.
- useState, onClick, document 같은 브라우저 상호작용이 필요하면 해당 부분을 Client Component로 만든다.

'use client'의 의미
- 'use client'는 그 파일을 Client Component 경계로 표시한다.
- 이 경계 안의 코드는 브라우저에서도 실행될 수 있도록 클라이언트 번들에 포함된다.
- 그러므로 페이지 전체를 Client Component로 만들기보다 상호작용이 필요한 작은 컴포넌트에 경계를 두는 것이 좋다.

예제의 데이터 흐름
1. page.js는 기본 Server Component로 메뉴 이름과 분류를 준비한다.
2. page.js는 메뉴 이름을 props로 MenuFavoriteButton에 전달한다.
3. MenuFavoriteButton 파일은 'use client'로 표시되어 useState와 onClick을 사용할 수 있다.
4. 버튼 클릭으로 Client Component의 state가 바뀌고 React가 버튼 UI를 갱신한다.

서버와 브라우저의 역할
- 서버는 페이지의 초기 내용을 준비하고, 클라이언트는 상호작용이 필요한 부분을 활성화한다.
- Server Component에서 Client Component로 전달하는 props는 서버와 브라우저 사이에 전달할 수 있는 직렬화 가능한 값이어야 한다.
- 함수나 브라우저 객체를 일반 props처럼 경계를 넘어 전달할 수는 없다.

생각해 보기
- 메뉴 이름과 분류를 보여 주는 데 클릭 state가 꼭 필요할까?
- 즐겨찾기 버튼만 Client Component로 분리하면 브라우저에서 처리할 코드는 어떻게 달라질까?
- 모든 page.js에 'use client'를 붙이면 어떤 비용과 제약이 생길까?
