# React 강의 추가 제안

## 분석 범위

`001_useState`부터 `014_router2`까지의 강의 코드와 필기를 살펴보았습니다. 강의는 메뉴 예제를 중심으로 상태, 목록, 컴포넌트, 폼, 비동기 데이터, Next.js 라우팅까지 순서대로 확장하고 있습니다.

## 현재 강의에서 다루는 내용

| 강의 | 다루는 핵심 내용 |
| --- | --- |
| 001–002 | 함수 컴포넌트, JSX, `useState`, 이벤트, 입력 미리보기, 배열에 추가·삭제 |
| 003–006 | 객체 배열과 `map`·`key`, Props, `children`, JavaScript `Map` 선택 확장 |
| 007–010 | 폼 제출, 입력 상태, 불변 업데이트, Callback Props, 조건부 렌더링 |
| 011–012 | `useEffect`, 비동기 요청 흐름, 로딩·오류·빈 결과 |
| 013–014 | Next.js App Router, `Link`, 동적 경로, 상세 페이지, `notFound()` |

기초부터 라우팅까지의 주요 흐름은 이미 갖춰져 있습니다. 새 훅을 많이 추가하기보다는, 실제 서비스에서 필요한 경계와 오류 처리, 종합 실습을 보완하는 편이 좋습니다.

## 보완을 권하는 내용

### 우선 보완: Server Component와 Client Component

현재 `useState`, 이벤트, `useEffect`를 사용하는 페이지에는 `'use client'`가 있습니다. 하지만 Next.js App Router에서는 페이지와 레이아웃이 기본적으로 Server Component라는 점, 상호작용이 필요한 부분에만 Client Component 경계를 두는 방법을 다루는 강의가 없습니다.

- 권장 위치: `012_async_data` 다음, `013_router` 전후
- 다룰 내용:
  - Server Component와 Client Component의 기본 차이
  - `'use client'`가 필요한 경우와 파일 경계의 의미
  - 서버에서 가져온 데이터를 Client Component에 props로 전달하기
  - 브라우저 API, 이벤트, Hook을 서버 컴포넌트에서 사용할 수 없는 이유
- 제안 폴더명: `015_server_client_components`

### 폼 입력 검증과 사용자 피드백

`007_form_events`에서 `required`, `min`과 입력값 초기화를 다루지만, 공백만 입력한 경우나 잘못된 입력을 사용자에게 안내하는 방법은 충분히 다루지 않습니다. 현재 예제의 유효하지 않은 이름은 화면에 오류 없이 제출만 무시됩니다.

- 새 챕터를 만들기보다 `007_form_events`를 확장하는 것을 권장합니다.
- 공백 제거 후 유효성 검사, 오류 문구 표시, 성공 후 입력 초기화, 숫자 입력의 범위 검증을 추가합니다.
- 오류 상태와 제출 결과를 조건부 렌더링하는 연습으로 `010_conditional_rendering`과 연결합니다.

### 실제 요청과 Effect 정리

`012_async_data`는 `setTimeout`으로 요청을 흉내 내고 `isActive` 플래그로 정리 시 오래된 결과를 무시합니다. 로딩·오류·빈 결과 흐름을 배우기에는 적절하지만, 실제 네트워크 요청의 취소와 컴포넌트 재요청 상황은 다루지 않습니다.

- `fetch`로 데이터를 가져오는 예제를 추가하거나, 네트워크 없이 실습할 수 있도록 현재 모의 요청 예제를 유지한 채 확장 예제를 둡니다.
- `AbortController`를 사용해 요청을 취소하는 경우와 의존성이 바뀌어 이전 요청이 더 이상 유효하지 않은 경우를 설명합니다.
- 개발 모드의 Effect 재실행과 cleanup의 관계도 간단히 짚습니다.
- 외부 API 연결을 필수로 만들기보다는, 실행 환경에 따라 기존 모의 데이터로도 완주할 수 있게 합니다.

### 종합 실습으로 챕터 연결

각 주제는 작고 명확한 예제로 설명되어 있습니다. 이제 별도 종합 실습에서 앞서 배운 내용을 연결하면 학습자가 개념을 실제 앱의 흐름으로 경험할 수 있습니다.

1. `01-Menu-CRUD-IntegratedExample`
   - 활용 강의: `001`–`010`
   - 메뉴 등록·수정·삭제, 즐겨찾기, 입력 검증, 빈 목록과 결과 목록을 구현합니다.
   - Props와 Callback Props로 폼·목록·메뉴 카드를 분리합니다.
2. `02-Menu-Data-IntegratedExample`
   - 활용 강의: `003`–`012`
   - 목록과 상세 데이터를 연결하고, 로딩·오류·빈 결과 상태를 포함합니다.
   - 현재 모의 요청을 먼저 완성한 뒤 실제 API 연결은 선택 확장으로 둡니다.
3. `03-Menu-Routing-IntegratedExample`
   - 활용 강의: `003`–`005`, `013`–`015`
   - 재사용 가능한 메뉴 카드에서 동적 상세 경로로 이동하고, 존재하지 않는 ID를 처리합니다.
   - Server/Client Component 경계를 적용해 봅니다.

## 선택 확장

아래 내용은 초급 필수 과정에 한꺼번에 넣기보다, 종합 실습을 마친 뒤 필요한 순서로 추가하는 것을 권합니다.

- **`useReducer`**: 여러 상태 변경 규칙이 한 컴포넌트에 모일 때 메뉴 상태를 reducer로 관리합니다. `008_immutable_state`의 배열 업데이트를 익힌 뒤 소개합니다.
- **Context**: 여러 단계로 props를 전달해야 하는 상황에서 공통 상태를 공유합니다. Callback Props와 상태 끌어올리기를 먼저 이해한 뒤 다룹니다.
- **Custom Hook**: 여러 컴포넌트에서 반복되는 상태·Effect 로직을 재사용합니다. `useEffect`와 비동기 요청을 이해한 다음 소개합니다.
- **`useRef`**: 입력 요소에 포커스를 주거나 렌더링과 별개로 값을 보관하는 예제로 다룹니다.
- **테스트**: 입력, 추가, 삭제, 오류 표시 등 사용자가 보는 동작을 테스트합니다. 종합 실습 이후 선택 과정으로 적합합니다.

## 권장 진행 순서

1. 현재 `001`–`014` 흐름은 유지합니다. `006_map_optional`은 문서대로 선택 학습으로 둡니다.
2. `007_form_events`에 입력 오류와 성공 피드백을 보강합니다.
3. `012_async_data`에 요청 취소와 Effect 재실행 설명을 추가합니다.
4. `015_server_client_components`를 라우팅 학습 전후에 배치합니다.
5. 먼저 CRUD 종합 실습을 진행하고, 이후 데이터 요청과 라우팅 종합 실습으로 확장합니다.
6. `useReducer`, Context, Custom Hook, `useRef`, 테스트는 선택 확장으로 둡니다.

## 결론

현재 강의에는 React 입문 과정의 핵심인 state, 목록 렌더링, Props, 폼, 불변 업데이트, 이벤트 전달, 조건부 렌더링이 이미 포함되어 있습니다. 가장 큰 보완점은 Next.js App Router에서 중요한 Server/Client Component 모델이며, 그다음은 폼 검증과 실제 요청 취소입니다. 추가 Hook을 모두 필수로 넣기보다 종합 예제로 현재 내용을 연결한 뒤 선택 주제를 단계적으로 확장하는 구성을 권합니다.
