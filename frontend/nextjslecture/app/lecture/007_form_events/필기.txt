강의 필기: 폼 이벤트와 입력 데이터 흐름

핵심 개념
- 폼은 사용자의 여러 입력값을 모아 하나의 작업으로 제출한다.
- controlled form은 React state를 입력값의 기준으로 삼는다.
- 브라우저 이벤트는 사용자의 입력과 제출을 JavaScript 코드에 전달한다.

제출이 처리되는 순서
1. 사용자가 input을 수정하면 onChange 이벤트가 발생한다.
2. event.target의 name과 value로 변경된 필드를 확인한다.
3. setForm으로 새 form 객체를 만들고 React에 state 변경을 요청한다.
4. 제출 이벤트에서 preventDefault()를 호출해 브라우저의 기본 페이지 이동/새로고침을 막는다.
5. 입력을 검사하고 유효하면 새 메뉴 배열을 만들어 state에 저장한다.
6. React가 새 배열로 목록을 다시 렌더링하고, 입력 state를 초기값으로 되돌린다.

브라우저 검증과 애플리케이션 검증
- required와 min은 브라우저가 제공하는 기본 입력 검증이다.
- 공백만 있는 이름은 required만으로 걸러지지 않으므로 trim() 후 직접 검사한다.
- 잘못된 입력에는 이유를 사용자에게 알리고, 다시 입력하거나 초기화할 때 오류 안내를 지운다.
- input의 value는 숫자 칸이어도 문자열이다. 계산이나 숫자 저장 전에 Number()로 변환한다.

state를 안전하게 갱신하기
- form은 객체이므로 기존 객체의 한 속성만 바꾸지 않고 나머지 속성을 복사해 새 객체를 만든다.
- 메뉴 목록도 기존 배열을 직접 수정하지 않고 새 배열을 만든다.
- type="submit"은 제출을 발생시키고, type="button"은 폼 제출 없이 별도 동작을 한다.

생각해 보기
- preventDefault()를 빼면 브라우저에서 어떤 일이 일어날까?
- 숫자 input의 value가 문자열인 이유와 Number() 변환이 필요한 시점을 설명해 본다.
