강의 필기: 데이터와 동적 상세 경로 연결

핵심 개념
- 동적 라우트는 URL의 일부를 데이터 식별자로 사용해 같은 페이지 구조로 여러 항목을 보여 준다.
- URL 경로와 메뉴 데이터는 서로 다른 역할을 한다. 경로는 어떤 항목인지 가리키고, 데이터는 그 항목의 내용을 제공한다.
- ID와 상세 화면을 분리하면 메뉴마다 별도의 page.js를 만들 필요가 없다.

목록에서 상세 화면까지
1. menuData.js는 id, name, category, price, description을 가진 메뉴 객체 배열을 제공한다.
2. 목록 페이지는 배열을 map()으로 순회해 각 메뉴의 상세 URL을 만든다.
3. 사용자가 링크를 누르면 /menus/[menuId] 경로로 이동한다.
4. Next.js는 URL의 pasta 같은 값을 params.menuId로 전달한다. Next.js 16에서 params는 Promise이므로 await한다.
5. find()가 배열에서 ID가 일치하는 메뉴를 찾고, 찾은 객체로 상세 화면을 만든다.
6. 일치하는 데이터가 없으면 notFound()로 404를 표시한다.

데이터 구조와 식별자
- URL의 ID는 메뉴 이름이나 배열의 현재 위치가 아니라 메뉴를 안정적으로 구별하는 값이다.
- find()는 배열을 앞에서부터 확인해 조건에 맞는 첫 항목을 찾는다.
- 데이터를 새로 추가할 때 메뉴 ID가 URL 규칙과 일치해야 상세 화면에서 다시 찾을 수 있다.

이 구조의 장점
- 항목 수가 늘어도 상세 화면 템플릿은 한 번만 작성한다.
- 데이터를 추가하면 같은 상세 페이지 구조가 그 데이터를 표시한다.
- 주소를 공유하면 해당 메뉴를 다시 찾아갈 수 있다.

생각해 보기

- URL, params, menuData의 id, find() 결과가 어떻게 연결되는지 순서대로 설명해 본다.
