강의 필기: 불변 업데이트와 React state

핵심 개념
- React 렌더링은 현재 state와 props를 입력으로 화면을 계산한다.
- state의 배열이나 객체를 직접 바꾸면 이전 값과 새 값의 차이를 추적하기 어려워진다.
- 대신 변경된 새 배열이나 새 객체를 만들어 setter에 전달한다. 이전 state는 그대로 남는다.

불변 업데이트의 의미
- 배열을 새로 만들면 React와 개발자는 새 state가 생겼다는 것을 명확히 다룰 수 있다.
- 객체를 복사한 뒤 일부 속성만 바꾸면, 기존 객체와 새 객체가 서로 다른 값으로 분리된다.
- 이 방식은 렌더링뿐 아니라 이전 값과 현재 값을 비교하거나 업데이트를 추적할 때도 유리하다.

메뉴 데이터의 상태 전이
- 추가: 기존 메뉴 배열 뒤에 새 메뉴를 붙인 새 배열을 만든다.
- 수정: map()으로 배열을 순회해 대상 메뉴만 복사한 새 객체로 바꾼다.
- 삭제: filter()로 삭제 대상이 빠진 새 배열을 만든다.
- 즐겨찾기 전환: 대상 객체를 복사하고 isFavorite 값만 반대로 설정한다.

함수형 state 갱신
- 새 state가 이전 state에 의존하면 setter에 함수를 전달한다.
- React는 그 함수에 실제로 적용할 최신 state를 제공한다.
- 여러 업데이트가 모여 처리되거나 빠르게 연속 요청될 때 오래된 렌더의 값을 사용하는 위험을 줄인다.

예제의 동작 흐름
1. 사용자가 메뉴 추가, 즐겨찾기 전환 또는 삭제를 요청한다.
2. 해당 배열 연산은 원본을 변경하지 않고 새 배열을 만든다.
3. setter에 새 배열이 전달되면 React가 업데이트를 예약한다.
4. 컴포넌트가 새 배열로 다시 실행되고, 목록 UI가 갱신된다.

생각해 보기
- 기존 배열에 push()한 뒤 같은 배열을 setter에 넣으면 무엇이 불명확해질까?
- 수정은 map(), 삭제는 filter()가 어울리는 이유를 데이터 흐름으로 설명해 본다.
