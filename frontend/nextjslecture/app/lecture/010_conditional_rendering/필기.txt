강의 필기: 상태에 따라 화면 분기하기

핵심 개념
- 화면은 현재 데이터와 상태를 바탕으로 계산된다.
- 조건부 렌더링은 현재 상황에 맞는 JSX만 선택해 반환하는 방식이다.
- 로딩, 오류, 빈 결과, 데이터 있음은 서로 다른 UI 상태다.

예제의 상태 전이
1. view state는 현재 화면 모드를 loading, error, empty, data 중 하나로 나타낸다.
2. 버튼 클릭은 setView()를 호출해 다음 상태를 요청한다.
3. React가 새 state로 컴포넌트를 다시 실행한다.
4. renderMenuContent()는 위에서부터 조건을 확인하고 처음 맞는 화면을 반환한다.
5. data 상태에서는 메뉴 배열을 map()으로 화면 목록에 변환한다.

분기와 제어 흐름
- if 문에서 JSX를 반환하면 여러 화면 상태를 명확히 분리할 수 있다.
- 조건이 맞아 return하면 이후 조건은 검사하지 않는다.
- 짧은 표시에는 조건 연산자나 &&를 쓸 수 있지만, 상태가 여러 개면 명시적 분기가 읽기 쉽다.
- 이 예제의 버튼은 API 결과를 바꾸는 것이 아니라 화면 상태를 학습용으로 전환한다.

실제 앱에서 중요한 이유
- 사용자는 요청 중인지, 실패했는지, 결과가 없는지 알아야 다음 행동을 결정할 수 있다.
- 데이터 배열이 비어 있는 것과 요청이 실패한 것은 다른 상황이므로 화면도 구분해야 한다.
- role="status", role="alert", aria-live 같은 접근성 표식은 상태 변화를 보조 기술에 전달하는 데 도움을 준다.

생각해 보기
- 메뉴 배열이 비어 있어도 요청이 성공한 경우와 요청 자체가 실패한 경우는 왜 다른가?
- 화면 상태가 많아질 때 if 분기와 여러 조건 연산자 중 어느 쪽이 이해하기 쉬울까?
