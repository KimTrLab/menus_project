강의 필기: 비동기 데이터 요청과 상태 관리

핵심 내용
- API 요청은 즉시 끝나지 않으므로 Promise와 async/await로 결과를 기다린다.
- 화면에서는 보통 요청 중(loading), 성공(data), 실패(error) 상태를 구분한다.
- useEffect 안에서 데이터를 불러올 때 effect callback 자체를 async로 만들기보다, 내부 async 함수를 선언해 실행한다.

예제 흐름
1. 컴포넌트가 마운트되거나 shouldFail이 바뀌면 effect가 요청을 시작한다.
2. 요청 전에 status를 loading으로 바꾸고 이전 오류 메시지를 지운다.
3. try/catch에서 성공 데이터 또는 오류를 state에 저장한다.
4. status에 따라 로딩 안내, 오류 메시지, 데이터 목록 중 하나를 조건부 렌더링한다.
5. cleanup에서 isActive를 false로 바꾸어 effect 정리 이후의 오래된 결과를 무시한다.

실제 앱과 연결
- 이 예제는 setTimeout으로 API 요청을 흉내 낸다. 실제 프로젝트에서는 fetch 같은 요청 함수로 대체한다.
- Next.js 앱의 메뉴 조회와 채팅 요청도 같은 방식으로 로딩 및 오류 상태를 다룰 수 있다.
