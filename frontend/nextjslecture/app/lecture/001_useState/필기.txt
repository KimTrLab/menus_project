강의 필기: React 컴포넌트와 useState

핵심 용어
- 컴포넌트: 화면의 한 부분을 만드는 함수다. 현재 props와 state를 바탕으로 화면에 무엇을 보여 줄지 JSX를 반환한다.
- props: 부모 컴포넌트가 자식 컴포넌트에 전달하는 입력값이다. 이 예제에서는 props를 사용하지 않는다.
- state: 현재 컴포넌트가 기억하고 관리하는 상태값이다. 이 예제의 isFavorite이 state다.
- Hook: 함수 컴포넌트에서 React 기능을 사용하게 해 주는 함수다. useState가 Hook이고, state 자체를 Hook이라고 부르지는 않는다.
- JSX: JavaScript 안에서 HTML과 비슷한 문법으로 화면의 구조와 내용을 표현하는 방법이다.

React는 어떻게 화면을 갱신할까?
1. 처음 화면을 만들 때 React가 컴포넌트 함수를 실행한다.
2. 컴포넌트는 현재 state에 맞는 JSX를 반환한다.
3. 버튼을 누르면 setIsFavorite이 새 state를 React에 전달한다. 이 예제에서는 현재 값의 반대 값을 요청한다.
4. React는 새 state를 기억하고 컴포넌트를 다시 실행해 새로운 JSX를 만든다.
5. React는 이전 JSX 결과와 새 결과를 비교하고, 달라진 부분만 실제 DOM에 반영한다. 그래서 개발자가 DOM을 직접 바꾸지 않아도 화면이 state와 맞게 갱신된다.

이 예제의 동작 순서
- 처음에는 isFavorite이 false이므로 즐겨찾기 안내와 버튼 문구가 기본 상태로 보인다.
- 버튼을 누르면 updater 함수가 현재 state를 받아 반대 값을 반환한다.
- state가 true가 되면 JSX의 조건식이 다른 안내 문구와 버튼 문구를 선택한다.
- 다시 누르면 state가 false로 바뀌고, 화면도 처음 문구로 돌아간다.

직접 DOM 조작 예제와 비교하기
- dom-direct-control.html은 document.getElementById()로 요소를 찾고 textContent를 직접 변경한다.
- React 예제는 state를 변경하고, state에 따라 JSX가 무엇을 보여 줄지 표현한다. 실제 DOM 갱신은 React가 처리한다.
- 두 예제를 각각 눌러 보고, 화면을 바꾸기 위해 코드에서 무엇을 직접 변경하는지 비교한다.

기억할 점
- useState(false)는 초깃값 false인 state와 setter 함수를 제공한다.
- state 값을 직접 대입하지 않는다. setter를 호출해 React에 다음 state를 요청한다.
- useState는 React Hook이며, 함수 컴포넌트의 최상위에서 같은 순서로 호출한다.
- Next.js에서 Hook과 클릭 이벤트를 사용하는 이 페이지에는 'use client'가 필요하다.
