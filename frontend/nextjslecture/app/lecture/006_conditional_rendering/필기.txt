강의 필기: 조건부 렌더링

왜 필요한가
- 데이터 요청이나 사용자 동작의 상태에 따라 보여 줄 화면이 달라진다.
- Next.js 앱의 홈페이지는 데이터 로딩 중 문구를 표시하고, 채팅 화면은 답변을 기다리는 동안 안내 문구를 추가한다.
- 앞선 강의에서 배운 state를 화면 출력 조건으로 활용한다.

예제 흐름
1. view state에 loading, error, empty, data 중 현재 화면 상태를 저장한다.
2. 버튼을 누르면 setView()가 state를 바꾸고 React가 컴포넌트를 다시 렌더링한다.
3. renderMenuContent()는 if 조건을 위에서부터 검사하고 해당하는 JSX를 반환한다.
4. 데이터가 준비된 경우에는 배열의 map()으로 메뉴 목록을 만든다.

조건부 렌더링에서 기억할 점
- 조건문 안에서 JSX를 반환하면 상황별 화면을 명확하게 나눌 수 있다.
- 조건을 위에서부터 검사하는 경우, 먼저 반환한 조건 뒤의 코드는 실행되지 않는다.
- 실제 API를 연결할 때는 로딩, 오류, 결과 없음, 데이터가 있는 상태를 구분해 사용자에게 알맞은 화면을 제공한다.
- 간단한 표시에는 조건 연산자나 &&를 사용할 수도 있지만, 여러 상태가 있으면 명시적인 조건문이 읽기 쉽다.
